【需求描述】设置面板 UI 结构与重构规范

1. 底部 Bar 按钮合并

将底部 Bar 中原本独立的 5 个按钮（【版面】、【字体】、【样式】、【代码】、【表格】）合并为一个 【设置】 按钮，图标统一采用原【版面】按钮的齿轮图标（⚙️）。

2. 右侧面板合并

将原先五个按钮各自对应的右侧面板（【版面调节】、【字体调节】、【样式调节】、【代码样式调节】、【表格样式调节】）中的所有配置选项，全部合并到一个全新的面板中，面板名称为 【设置】，面板标题栏显示为 齿轮图标 + “设置”。

3. 新【设置】面板的菜单架构（一级与二级菜单）

新的【设置】面板不再保留原先的五个独立面板布局，而是采用类似 Windows 系统属性窗口（System Properties Dialog） 的标准选项卡导航架构，划分为 一级菜单（Tab 页签） 与 二级内容面板（Tab Content Area）。

3.1 界面布局示意图

+-----------------------------------------------------------------------+
|  ⚙️ 设置                                                             ✕ |
+-----------------------------------------------------------------------+
|  [主题]  [版面]  [字体]  [行内代码]  [代码块]  [引用]  [表格]          | <-- 一级菜单 (Tab 栏)
+-----------------------------------------------------------------------+
|                                                                       |
|  [二级菜单与配置内容展示区]                                             | <-- 二级菜单 (内容面板)
|                                                                       |
+-----------------------------------------------------------------------+

3.2 一级菜单（Tab 选项卡导航）

  • 展示位置：紧贴面板标题栏下方，位于设置面板的最顶部。
  • 展示形态：采用单行横向排布的 Tab 页签组（Tab Bar）。点击不同页签仅在当前面板内无刷新切换视图，不跳转页面。
  • 菜单项列表（按从左到右顺序横向排列，共 7 项）：
    1. 【主题】
    2. 【版面】
    3. 【字体】
    4. 【行内代码】
    5. 【代码块】
    6. 【引用】
    7. 【表格】

3.3 二级菜单与配置内容（Tab Content Pane）

根据一级菜单的标题，将原先五个面板中的配置选项分类放入对应的二级菜单下。分类映射如下：

一级菜单 二级菜单内容来源与配置项目
【主题】
  • 原【样式调节】面板中的 日间主题、夜间主题 下拉选择框（注意：下拉选项中需彻底移除原“自定义 / 当前颜色”选项）。
  • 原【字体调节】面板中的 【文字颜色】 和 【背景】 两个颜色选择器（需移动到本菜单下与主题下拉框组合）。
【版面】 原【版面调节】面板中的 画布小手开关、版面宽度滑块、版面位置滑块。
【字体】 原【字体调节】面板中的 文字大小滑块、文本行距滑块，以及经过改造的 五大文本元素动态字体配置区域（详见第 4 条）。
【行内代码】 原【代码样式调节】面板中的 行内主题下拉列表、行内字号滑块、行内边距滑块。
【代码块】 原【代码样式调节】面板中的 显示格式下拉列表（文字精简，详见第 5 条）、块级主题下拉列表（文字精简，详见第 6 条）、块级字号滑块、显示行号开关、顶部工具栏开关。
【引用】 原【样式调节】面板中的 引用样式下拉列表。
【表格】 原【表格样式调节】面板中的 显示格式下拉列表、显示标题栏开关。

3.4 视觉风格与交互

  • 一级菜单横向排布在面板最上方，类似于 Windows 系统属性窗口的标签页。点击一级菜单项，下方的配置区域切换到对应的一级菜单内容，不跳转页面，仅在面板内切换视图。
  • 内容滚动：二级面板内部若内容超出纵向高度，需独立开启 overflow-y: auto 纵向滚动，保持顶部一级菜单区域锁定固定，不随内容滚动。
  • 卡片式分组：二级面板内的配置选项宜采用浅色边框或卡片背景进行块状分组，确保复杂配置界面的条理清晰与视觉可读性。

4. 【字体】一级菜单下的配置改造

4.1 移除旧表格

完全移除原【字体调节】面板中的字体矩阵表格。

4.2 替换为五个区域（每个区域包含开关 + 下拉列表）

将原来的表格替换为五个独立的配置区域，每个区域对应一个文本元素类型：

  • 【标题】
  • 【正文】
  • 【代码】
  • 【链接】
  • 【引用】

每个区域包含三个控件：

  1. 【等宽】开关：样式与现有【代码样式调节】面板中的【显示行号】开关一致（ON/OFF 滑动开关）。
  2. 【衬线】开关：样式同上。
  3. 【字体选择】下拉列表：下拉列表的选项不是固定的，而是根据当前区域的两个开关状态，从系统字体中动态筛选并列出对应的字体。

动态筛选逻辑举例：

  • 如果用户为【正文】区域打开了【等宽】开关，关闭了【衬线】开关，则下拉列表中只显示系统上可用的 “等宽无衬线” 字体。
  • 如果两个开关都打开，则显示 “等宽衬线” 字体。
  • 如果两个开关都关闭，则显示 “变宽无衬线” 字体。
  • 如果只打开【衬线】，则显示 “变宽衬线” 字体。

用户选择列表中的任意字体后，正文中对应元素（如 #article-container 下的正文文本）立即切换为该字体。

显示要求：由于字体名称可能很长，下拉列表需要单独一行显示，若字体名称过长导致下拉框无法完全显示，需通过悬浮框（Tooltip）或悬停展开的方式完整展示字体全名。

4.3 颜色选择器移动

原【字体调节】面板中的 【文字颜色】 和 【背景】 两个颜色选择框，移动到【主题】一级菜单下，与日间/夜间主题下拉框放在一起。原【主题】菜单中【日间主题】和【夜间主题】下拉列表中的 【自定义 / 当前颜色】 选项需要移除，因为当用户通过颜色选择器选择颜色时，就已经表明它要基于当前主题使用自己的颜色，不再需要这个独立的选项入口。

5. 【代码块】一级菜单下【显示格式】选项文字精简

原【代码样式调节】面板中，【显示格式】下拉列表的选项文字过长，需要精简为更短的表达：

原文字 精简后文字
同宽 + 横向滚动 -- default 继承主题（作为默认选项）
同宽 + 横向滚动 横向滚动
同宽 + 自动换行 自动换行
自适应最长行 自适应宽

精简后的下拉列表选项顺序为：

  1. 继承主题（默认）
  2. 横向滚动
  3. 自动换行
  4. 自适应宽

6. 【代码块】一级菜单下【块级主题】选项文字精简

原【代码样式调节】面板中，【块级主题】下拉列表的第一个选项文字 跟随全局主题 -- default 需要修改为 继承主题，并保持其默认选项的地位不变。
