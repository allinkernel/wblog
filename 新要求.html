【前端 UI 与功能修缮需求文档】

一、 全局滚动条（Scrollbar）CSS 样式重构

问题描述： 当前整个前端框架中（包括：表格横向滚动条、左侧大纲/文档视图滚动条、代码块横向滚动条、右侧【设置】面板纵向滚动条等）使用的是原生且较宽的白色轨道滚动条，在深色主题下显得非常突兀且影响美观。

修改要求：

  1. 自动隐藏与悬停显示： 默认状态下隐藏所有滚动条（或设置滑块透明），只有当鼠标移动/悬停（Hover）到对应的视图容器区域时，才显示滚动条。
  2. 主题自适应与视觉和谐： 滚动条的颜色需根据全局主题（日间/夜间模式）自动适配，滑块颜色需与当前深色/浅色背景和谐融合。
  3. 精简外观（去除白色轨道）：
    • 移除原生的白色背景轨道（Track）。
    • 缩小滑块宽度/高度（推荐设置为 4px ~ 6px 的细滑块，并带圆角 border-radius）。
    • 仅保留一个简约的滑块（Thumb），实现类似 macOS 或现代 IDE 的现代滚动条样式（可使用 ::-webkit-scrollbar 系列伪元素或 Overlay 滚动条方案实现）。

二、 【设置】面板 -> 【字体】Tab 页下的【元素字体】拆分

问题描述： 目前在“设置”面板的“字体”一级菜单下，“元素字体”配置区域中只有一个统一的【代码】配置块。

修改要求：

  1. 将原有的 【代码】 配置块彻底拆分为两个独立的配置块：
    • 【行内代码】（包含：[等宽] 开关、[衬线] 开关、动态字体下拉列表）
    • 【代码块】（包含：[等宽] 开关、[衬线] 开关、动态字体下拉列表）
  2. 拆分后，拆分出的两个配置块需分别精准控制页面中的 code（行内代码）与 pre / pre code（块级代码）对应的字体样式。
  3. 拆分后的元素字体完整顺序应为： 【标题】 -> 【正文】 -> 【行内代码】 -> 【代码块】 -> 【链接】 -> 【引用】。

三、 渲染视图中表格（Table）背景色无法跟随内容完整延伸问题修复

问题描述： 当表格内容超出容器宽度产生横向滚动时，表格的背景色（如暗色背景块）仅覆盖了当前可视区域的宽度（大约只有内容总宽度的一半），当向右滚动查看更多表格列时，超出部分的内容右侧背景失效变成透明/透出底色。

修改要求：

  1. 修复表格容器（table 或其外层 wrapper 容器）的 CSS 布局。
  2. 确保表格背景色（background-color）、边框（border）能够跟随表格实际总内容宽度（scrollWidth / 100% 内联展示）完美包裹延伸，解决横向滚动时后半段内容无背景色（背景断层）的问题。
  3. （提示：可检查表格外层容器的 display: inline-block / min-width: 100% 或 width: fit-content 配置）
